# バックエンド（Convex）レビュー観点

## 設計／責務

- mutation / query のラッパーは薄く、ロジックは TypeScript 関数に分離されている
- 認可チェックは custom function または共有ヘルパーで一貫している

## Convex 必須

- public 関数に `args` と `returns` validator がある
- `await` 漏れがない
- query 内で `Date.now()` を使っていない
- 大きな一覧は `.collect()` ではなく pagination / index を検討している
- `ctx.db.get` / `patch` / `delete` にテーブル名がある（プロジェクト規約に従う）

## セキュリティ

- 認証・認可が適切で、権限のない操作が拒否される
- 入力値検証が不足しておらず、想定外入力が許容されない
- 機密情報がレスポンスやログに露出しない
- エラーメッセージに内部実装の過剰な露出がない

## パフォーマンス

- index を使ったクエリになっている（不要な `.filter()` スキャンがない）
- N+1 に近い読み取りパターンがない
- OCC 競合しやすい read-modify-write がないか

## テスト

- 正常系／異常系／境界値がカバーされている
- 認可拒否の失敗ケースがある
