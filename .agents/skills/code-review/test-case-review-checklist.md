# テストケース判定レビュー

## 対象ファイルの確認

- 変更したロジックに対応する `.test.{ts,tsx}` / `convex/**/*.test.ts` / `e2e/*.spec.ts` が存在するか
- 正常系だけでなく、エッジ・準異常・異常系のパターンがカバーされているか
- ユニット / コンポーネント / Convex / E2E の使い分けが適切か

## 正常系の判定

- テスト名が「何を・どの条件で・どうなるか」を示しているか
- `expect` の期待値が業務的に正しいか、ただ pass するための値ではないか
- コンポーネント・E2E ではユーザーが確認できる状態を assert しているか
- 入力から出力までの因果関係が明確に書かれているか

## エッジケース

- 数値：0、最小、最大、境界値、境界の前後
- 文字列：空、最大長、空白、特殊文字、ホワイトスペース
- 配列/オブジェクト：空、1件、多数、重複
- 日付：月末、年跨ぎ、週跨ぎ、無効日、タイムゾーン
- 真偽値：全 true/false 組み合わせ
- 型/オプション：`undefined`、`null`、省略

## 準異常系

- 入力形式は不正だが到達しうる（whitespace、typo、旧データ形式、部分的入力）
- 状態不整合（未ログイン、未所属、権限不足、データが存在しない）
- 同時実行/競合（重複登録、楽観ロック、OCC 競合）
- 外部依存の不完全な状態（空画像、無効な AI レスポンス、未招待ユーザー、タイムアウト）
- 浮動小数点や誤差、端数処理（税計算、合計差額など）

## 異常系

- 認証・認可拒否
- バリデーションエラー・不正入力
- 外部サービス/DB/ネットワークエラー
- エラーメッセージ、返却型、ロールバック動作を assert
- E2E ではユーザーに表示されるエラー文言を確認

## アサーションの判定品質

- 発生だけでなく結果を assert しているか
- `toThrow` 時にメッセージや型まで確認しているか
- `not.toThrow` や `toBeDefined` だけの曖昧なテストを避けているか
- スナップショットテストは意図通りの diff か、不要な更新がないか
- 非同期の場合は `await` / `resolves` / `rejects` を正しく使っているか

## カバレッジの最適化

- ユニットで十分なら E2E 重複を避けているか
- E2E でしか確認できない導線/権限は E2E でカバーしているか
- responsive やブラウザ差分があるなら反映されているか
- テストデータとセットアップの重複がないか
