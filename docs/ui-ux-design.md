# 週1レシート入力Web家計簿 UI/UX設計

## 1. 目的

本ドキュメントは、MVP実装に向けたUI/UX方針を定義する。

本アプリのUIは、見た目の派手さよりも、週1回まとめて複数枚のレシートをリズムよく入力できることを最優先にする。

## 2. UX/UIコンセプト

コンセプトは「週末に溜まったレシートを、止まらず処理できる入力作業台」とする。

- 毎日入力する家計簿ではなく、週1回の片付け作業に最適化する
- 入力画面は、家計簿というよりレシート処理のワークベンチとして設計する
- 1枚入力するたびに、件数と合計の変化がすぐ見えるようにする
- 主要操作は `保存して次へ` を中心に置く
- MUIを使うが、標準Material Design感は抑え、静かで軽い独自テーマにする
- Tailwind CSSは画面骨格、余白、レスポンシブなどのレイアウト用途に限定する

## 3. デザイン方針

### 3.1 見た目

- 家計簿向けの落ち着いた生活感を重視する
- 業務ツールに近い、読みやすく操作しやすいUIにする
- 装飾的なカードや大きなヒーロー表現は使わない
- 角丸は8px以下を基本にする
- 余白は広げすぎず、入力作業に必要な情報密度を保つ

### 3.2 カラー

- 主色は深めのグリーンまたはティールを候補にする
- 削除などの危険操作は控えめなレッドを使う
- カテゴリ色は区別しやすさを優先し、強すぎる彩度を避ける

### 3.3 タイポグラフィ

- 画面内の見出しは大きくしすぎない
- 金額と件数は視認性を高める
- フォームラベルと補助文は短くする

## 4. ユーザーフロー

1. Googleアカウントでログインする
2. ダッシュボードで今週の支出状況を見る
3. `今週の入力を開始` または `入力を再開` を選ぶ
4. 週次入力画面で支出を連続入力する（手入力 + AI下書きキュー）
5. 必要に応じて AI下書きキューから一括登録する
6. 週次サマリーでカテゴリ別支出と前週比を見る
7. **週別支出推移グラフで対象週と直前2週間を比較し、棒のTooltipで週範囲と支出合計を確認する**

## 5. 画面構成

### 5.1 ダッシュボード `/`

目的は、今週の状況と入力再開導線をすぐ見つけられるようにすることである。

表示する情報:

- 今週の合計支出
- カテゴリ別支出
- 入力済みレシート件数
- 未完了セッション
- 前週比

主要操作:

- `今週の入力を開始`
- `入力を再開`
- `週次サマリーを見る`

注意:

- ダッシュボードを作り込みすぎない
- MVPでは、入力画面への導線を最も目立たせる

### 5.2 週次入力画面 `/weeks/current/input`

MVPで最も重要な画面とする。

現行コードでは、週ナビゲーション、`ExpenseEntryForm`（手入力）、`AiExpenseQueuePanel`（AI下書きキュー）を
配置する。スマートフォンでも入力フォームを最優先にし、保存後すぐ次の入力に進める。

表示する情報:

- 週ナビゲーション
- 手入力フォーム（`ExpenseEntryForm`）
- AI支出下書きキュー（見出し「レシート入力」）

主要操作:

- `保存して次へ`（手入力）
- AI下書きの確認・編集・まとめて登録

### 5.5 公開ページ

| パス | 目的 |
| --- | --- |
| `/privacy` | プライバシーポリシー（認証不要） |
| `/terms` | 利用規約（認証不要） |
| `/maintenance` | メンテナンス表示（認証不要） |

フッターから公開ページへ遷移できる。詳細は `src/features/app-shell/lib/publicPaths.ts` を参照する。

### 5.3 週次サマリー `/weeks/:weekStartDate`

目的は、入力後にその週の支出傾向を把握できるようにすることである。

表示する情報:

- 合計支出
- カテゴリ別支出
- 前週比
- **週別支出推移（対象週を含む直近3週間の棒グラフ）**
- 支出一覧

**週別支出推移グラフの仕様:**

- 対象週、1週前、2週前の支出合計をprimary色の棒で比較表示
- 現在週では `今週`、`先週`、`2週前`、過去週では `M/D週` のラベルを使う
- Y軸は金額に応じて `円`・`万円` で表し、PC・モバイルとも文字が見切れない余白を確保する
- グラフ上部に対象週の支出、前週差、直前2週間の平均比を通常テキストで表示する
- 棒のTooltipに週範囲と支出合計を表示する
- 凡例は表示せず、モバイルでも約220pxの固定高でラベルを読み取れるようにする
- 空状態: 「週別の支出データがあると表示されます」
- ローディング: Skeleton で表示

主要操作:

- 支出を修正する
- **グラフの棒をホバーまたはタップして週ごとの比較を見る**

### 5.4 設定 `/settings`

MVPでは深く作り込まず、入力体験を支える最低限の管理画面にする。`/categories` は同じ
設定画面への互換ルートとして扱う。

グループ管理（メンバー・招待）のセクション構成と owner/member の表示差分は
`docs/group-admin-ui-layout.md` を正本とする。

主要操作:

- グループ名・メンバー・招待を管理する（詳細は `docs/group-admin-ui-layout.md`）
- カテゴリを追加する
- カテゴリ名を変更する
- カテゴリ色を変更する
- カテゴリを無効化する
- 週の開始曜日・終了曜日を保存する

### 5.6 システム管理 `/admin`

通常利用者の設定画面と分離し、active なシステム管理者だけが利用する。画面ヘッダーには
現在の環境を常時表示し、「グループ owner」と「システム管理者」を明確に区別する。

権限確認、読込、空、エラー、付与・剥奪中の状態と確認ダイアログの詳細は
`docs/system-admin-authorization.md` を正本とする。管理画面から家計データは表示しない。

## 6. 支出入力フロー

入力順は以下を基本にする。

1. 日付（週内の曜日選択）
2. 店舗名 / 支払先
3. 合計金額
4. カテゴリ（単一項目、または複数支出項目モード）
5. メモ（任意）
6. 保存

### 6.1 日付

- 初期値は今日、または直前入力の日付にする
- 週内の日付を素早く選べるUIを用意する
- 保存後は前回値を引き継ぐ

### 6.2 店舗名 / 支払先

- 店舗名または支払先を入力する
- 保存後は店舗名/支払先と金額、メモをクリアする

### 6.3 金額

- 合計金額と複数支出項目の内訳合計を扱う
- 複数支出項目モードでは、内訳合計と合計金額の差額を確認ダイアログで確認する
- 入力値は日本円の整数として扱う
- 表示上は円表記を補助する
- スマートフォンでは数字キーボードを出しやすい入力属性にする
- 0円以下は保存できない

### 6.4 カテゴリ

- 店名からカテゴリ候補を推定する
- 推定できない場合は、直近カテゴリやよく使うカテゴリを表示する
- カテゴリは `Chip` または小さな `Button` でタップしやすくする
- 推定が外れても修正しやすいUIにする
- `支出項目を追加` で複数カテゴリの内訳入力モードに切り替えられる

### 6.5 メモ

- 任意入力とする
- 通常の入力リズムを邪魔しないよう、折りたたみまたは小さな欄にする
- 上限文字数を設ける

### 6.6 保存

主ボタンは `保存して次へ` とする。

保存後の挙動:

- 日付を引き継ぐ
- カテゴリを引き継ぐ、または店名から再推定する
- 店舗名/支払先、金額、メモをクリアする
- Snackbar で「支出項目を保存しました」と通知する
- 保存結果をダッシュボードや週次サマリーへ反映する

### 6.7 AI支出下書きキュー

`AiExpenseQueuePanel`（見出し「レシート入力」）は、レシート/払込票画像の解析結果を
下書きとして確認してから `expenseEntries` に一括登録する主導線とする。

- `ready` と `needs_review` の違いを状態として見せる
- 必須項目が不足している下書きは、書類種別、日付、合計金額、店名・内容、カテゴリを編集できるようにする
- 支払場所、支払先、支払内容は編集画面へ個別表示せず、店名・内容へ統合する
- まとめて登録しても、通常の `expenseEntries` 保存と同じ認可・バリデーションを通す
- 解析中は「読み取り中」等の状態ラベルを表示する

## 7. UI状態

### 7.1 空状態

- ダッシュボードでは `今週の入力を開始` を主導線にする
- 説明文は短くする
- 未入力でも不安を感じない表示にする

### 7.2 ローディング

- MUI `Skeleton` を使う
- フォーム全体をスピナーで塞がない
- 既に表示済みの入力内容はできるだけ保持する
- Clerk / Convex の初期認証待ちは、Suzumemoロゴと左右の葉を使った3秒ループの全画面アニメーションを表示する
- 全画面アニメーションはSuzumemoのペーパーカラー1色を使った半透明オーバーレイとし、内側に別色の背景・枠・影を設けない
- ロゴは既存のSVGだけを使い、左右の葉が芽吹いたあと、英字と日本語の文字が順に現れ、全体を短く保持してからまとめて消える3秒ループにする
- アニメーション本体は `SuzumemoLoadingLogo`、配置と待機文言は `SuzumemoLoadingState` に分離し、`fullscreen` と `page` の表示方式を共通化する
- 認証、グループ確認、Dashboard、入力、週次サマリーなど画面全体またはページ全体を待つ状態には `SuzumemoLoadingState` を使う
- ボタン内の保存・送信中表示には小さい `CircularProgress`、既存レイアウトを保持する読込状態には `Skeleton` を引き続き使う
- 全画面アニメーションには待機内容の文言と `role="status"` を付け、`prefers-reduced-motion` では静止表示にする

### 7.3 保存中

- 保存ボタンのみ無効化する
- ボタン内に小さな `CircularProgress` を表示する
- 入力内容は消さない

### 7.4 保存成功

- MUI `Snackbar` で短く通知する
- ダッシュボードや週次サマリーの集計へ反映されることを確認しやすくする
- 通知は入力操作を邪魔しない位置に出す

### 7.5 入力エラー

- MUI `TextField` の `helperText` で項目ごとに表示する
- まとめエラーを上部に出しすぎない
- 金額、店名、カテゴリのエラーを優先して分かりやすくする

### 7.6 通信エラー

- MUI `Alert` と `再試行` ボタンを表示する
- オフラインキューはMVPでは実装しない
- 入力内容は消さない

### 7.7 セッション完了

- 完了後は `今週のサマリーを見る` を主ボタンにする
- 次に必要な操作を明確にする

## 8. MUIコンポーネント方針

MUIをUIコンポーネントの主軸にする。Tailwind CSSはMUIの代替ではなく、レイアウト補助として使う。

責務分担:

- MUI theme: 色、Typography、角丸、影、コンポーネント標準スタイル
- MUI `sx`: MUIコンポーネント単位の微調整、状態依存、theme参照が必要なスタイル
- MUI `styled`: 再利用する独自コンポーネントや複雑なスタイル
- Tailwind CSS: 画面全体のflex/grid、gap、padding、responsive、表示/非表示、外側ラッパー

`Button`、`TextField`、`Chip`、`Alert`、`Snackbar`、`Table` などのMUIコンポーネントの色、サイズ、角丸、状態表現はMUI themeを正とする。Tailwind CSSでMUIコンポーネント内部を深く上書きしない。

### 8.1 レイアウト

- `Container`
- `Stack`
- `Grid`
- `Box`

### 8.2 入力

- `TextField`
- `Autocomplete`
- `Select`
- `ToggleButtonGroup`
- `Button`

### 8.3 カテゴリ

- `Chip`
- 小さな `Button`

### 8.4 進捗と状態表示

- `LinearProgress`
- `Badge`
- `Skeleton`
- `CircularProgress`
- `Snackbar`
- `Alert`

### 8.5 一覧

- PCでは `Table` を使う
- スマートフォンでは縦積みのリスト表示にする
- スマートフォンで横スクロール前提の表は使わない

### 8.6 ナビゲーション

- PCではサイドナビまたはトップナビを使う
- スマートフォンでは下部ナビまたは上部の最小ナビを使う
- 入力画面ではナビゲーションを主張させすぎない

## 9. レスポンシブ方針

### 9.1 PC

- 週ナビゲーションと入力フォームを読みやすい幅で配置する
- 入力画面では手入力フォームとAI下書きキューを迷わず見つけられるようにする
- キーボード操作を重視する
- 入力後の確認はダッシュボードまたは週次サマリーへ自然に移動できるようにする

### 9.2 スマートフォン

- 1画面1タスクを基本にする
- `保存して次へ` を画面下部に固定する
- カテゴリはタップしやすいチップとして表示する
- 支出一覧はテーブルではなく縦積みリストにする
- サマリーは入力を妨げない位置に置く

## 10. 実装時の注意

- 入力フォームは再レンダリングでフォーカスが飛ばないようにする
- 保存後の初期値引き継ぎを仕様として固定する
- 金額は表示フォーマットと保存値を分ける
- カテゴリ推定は外れても邪魔にならないUIにする
- Tailwind CSSはレイアウト用途に限定し、MUIコンポーネントの見た目制御はMUI theme、`sx`、`styled` を優先する
- CSVエクスポートやオフライン対応は現行コードでは未実装であり、入力セッションの導線から外す
- ダッシュボードよりも、週次入力画面を先に作り込む
- E2Eでは、複数件の支出入力、複数支出項目モード、設定保存、週次サマリー確認、AI下書き一括登録を変更内容に応じて検証する
